Getting started

Installation and prerequisites

OD.MyLocalAgent runs on 64-bit Windows 10 or Windows 11. Published builds are self-contained and do not require a separately installed .NET runtime.

Essential requirements

  • Windows 10 or Windows 11 under your normal user account.
  • Ollama installed with its service running.
  • At least one local model, normally gemma4:12b.
  • Google and Dropbox accounts only when those connectors are needed.

Published layout

The UI and headless runner are intentionally separate. Windows Task Scheduler starts the runner.

%LOCALAPPDATA%\Programs\OD.MyLocalAgent\
├── UI\OD.MyLocalAgent.UI.exe
└── Runner\OD.MyLocalAgent.Runner.exe

Prepare Ollama

In PowerShell, check Ollama and install the recommended model:

ollama --version
ollama pull gemma4:12b
ollama list
The model tag shown by ollama list must exactly match the tag selected in the application. gemma4:12b and gemma4:latest are different identifiers.

Publish from the repository

If you have the source repository, open PowerShell at its root and run:

.\scripts\publish.ps1

Then start %LOCALAPPDATA%\Programs\OD.MyLocalAgent\UI\OD.MyLocalAgent.UI.exe.

Getting started

First start: the checklist

Perform these checks in order. They isolate model, runner, and permission problems before you create more complex tasks.

  1. Open Settings.

    Keep Ollama (local, default) selected for the first test.

  2. Check the endpoint and model.

    The usual local endpoint is http://localhost:11434. Select an installed model.

  3. Set File-system root path.

    For example, C:\OD.MyLocalAgent. File tools are confined to this directory.

  4. Leave Runner path empty.

    In the standard installation, the application locates the sibling runner automatically.

  5. Locate the folder and shortcut utilities.

    The copy icons place the reports and executable directories on the clipboard separately. Create desktop shortcut creates or refreshes the UI shortcut on the Windows desktop.

  6. Select Save settings.

    Wait for the message confirming that settings were saved and reloaded.

  7. Run Test connection.

    The result should report a healthy provider and display latency.

Allow sending email, Allow file deletion, and Allow HTTP POST are disabled by default. Do not enable them preemptively; wait until a reviewed workflow actually needs them.

Guided scenario 01

Configure Ollama and select a model

This scenario configures the default local provider and verifies that the selected model is installed on the target Ollama endpoint.

  1. Open Settings → AI provider.

    Select Ollama (local, default).

  2. Enter the endpoint.

    Normally use http://localhost:11434. For an approved remote Ollama server, enter its HTTP or HTTPS URL.

  3. Select Refresh models.

    The list is loaded from the entered endpoint. A failure is reported without switching to a cloud provider.

  4. Choose the model in the combo box.

    The field remains editable, but a manually entered tag must still exist in Ollama.

  5. Review AI generation defaults.

    Initial values are Temperature 0.2, Top P 1, and Context window 8192. Valid ranges are 0–2, greater than 0 through 1, and 1024–2000000. Tune Temperature or Top P first instead of changing both.

  6. Configure project-wide AI instructions when needed.

    Use Project-wide AI instructions only for durable project conventions, such as the response language or output format. In the Task editor, Apply project-wide AI instructions to this task is enabled by default; clear it to exclude one task. View system prompt displays the configured text or the opt-out state. Built-in safety rules, allowed tools, and the task remain authoritative.

  7. Keep a suitable timeout.

    The default 300 seconds allows for a slow first token from a large local model.

  8. Save, then test.

    Select Save settings, followed by Test connection.

A healthy result means both that the endpoint is reachable and that the configured model appears in the installed-model list.
Context window is the declared total budget—messages, agent/tool context, and response—not an output-token limit. Ollama receives it through native num_ctx. An OpenAI-compatible provider remains authoritative for its fixed capacity; no unsupported request field is invented.

Guided scenario 02

Create a fully local first task

This task creates a directory, writes a file, and reads it back. It requires no cloud account and validates storage, workflow execution, the runner, and reports.

  1. Prepare the allowed directory.

    In Settings, set File-system root path to a path such as C:\OD.MyLocalAgent, then save.

  2. Open Tasks and select New.

    The task editor opens.

  3. Enter the identity.

    Id: first-local-task · Name: First local task. The id accepts lowercase letters, digits, and hyphens.

  4. Add a descriptive prompt.

    For example: “Verify the local filesystem workflow and report the result.”

  5. Choose a schedule.

    Under Quick schedule, choose Every day at 09:00. Check the next three occurrences.

  6. Allow only File system.

    Leave every other group cleared in Tool whitelist.

  7. Paste the following into Workflow JSON.

    The editor expects the array of steps, not the complete task object.

Tool whitelist is generated from the tool catalog compiled into this version. Groups integrated by a future version therefore appear in this editor automatically and always start cleared. Selecting a group grants no filesystem location and changes no Safety setting; those controls remain independent. The catalog does not load external runtime plug-ins. 
[
  {
    "step": "filesystem.createDirectory",
    "id": "createWelcomeDirectory",
    "args": {
      "path": "welcome"
    }
  },
  {
    "step": "filesystem.write",
    "id": "writeWelcomeFile",
    "args": {
      "path": "welcome/hello.txt",
      "content": "OD.MyLocalAgent completed {{task.id}}."
    }
  },
  {
    "step": "filesystem.read",
    "id": "readWelcomeFile",
    "args": {
      "path": "welcome/hello.txt"
    }
  }
]
  1. Keep the task enabled and save it.

    Select Save task. Syntax, aliases, arguments, ids, and whitelist access are validated. If the definition is incomplete or invalid, a dialog explains that no changes were saved. Back asks for confirmation before discarding a changed draft.

  2. Run it immediately.

    Return to Tasks, select the row, and choose Run now.

  3. Check the result.

    Runner output should confirm success. The file welcome\hello.txt appears under the configured root.

Why this task is safe: it has only the filesystem group, every path is relative to the allowed root, and it does not request deletion.

Guided scenario 03

Test a prompt, then run the real task

Prompt testing supports fast iteration with streaming output. Run now then uses the same runner as Windows scheduling.

  1. Select a task in Tasks.

    Choose Prompt.

  2. Edit Agent prompt.

    State the expected outcome, output format, language, and limits.

  3. Select Save prompt.

    The text is written back to the task definition.

  4. Run Test the prompt.

    The answer streams into Streamed agent output. The task tool whitelist applies.

  5. Adjust and repeat if needed.

    Use Cancel to stop a long generation.

  6. Return to Tasks and choose Run now.

    If the task has a workflow, the workflow wins. Otherwise, the runner executes the prompt with the allowed tools.

A prompt test is not a workflow test. Test the prompt tests the agent and whitelist. Run now executes the actual task path and writes the normal report.

Guided scenario 04

Connect Gmail and Google Calendar

Google authorization is interactive. Complete it in the UI under the same Windows account that will run scheduled tasks.

Prepare Google Cloud

  1. Create or select a Google Cloud project.

    Enable Gmail API and Google Calendar API.

  2. Configure the OAuth consent screen.

    Add the intended account as a test user while the app remains in testing.

  3. Create an OAuth client of type Desktop app.

    Copy its Client ID and Client Secret.

  4. Close OD.MyLocalAgent and update settings.json.

    Preserve the file’s other sections and add or update the following section.

{
  "Google": {
    "ClientId": "YOUR_DESKTOP_CLIENT_ID",
    "ClientSecret": "YOUR_DESKTOP_CLIENT_SECRET"
  }
}

The file is %LOCALAPPDATA%\OD.MyLocalAgent\settings.json.

Authorize in the application

  1. Restart the application and open Tools.

    Google Workspace should report that OAuth client configuration is available.

  2. Select Connect.

    Complete consent in the browser with the intended Google account.

  3. Return to the application and refresh status.

    Use Refresh status if needed.

  4. Test Gmail and Calendar separately.

    Each Test connection performs a read-only check and displays latency.

  5. Enable only Gmail and/or Calendar on the task.

    OAuth consent does not replace the per-task whitelist.

Connect Dropbox

  1. Create an app in Dropbox App Console.

    Choose the narrowest access type possible, preferably an app folder.

  2. Enable only required permissions.

    Metadata read, content read, and content write as needed by the selected aliases.

    Enter the replacement values in the provided fields.

Guided scenario 06 · Cloud opt-in

Enable guarded Ollama Web Search

Web Search is disabled on a fresh install. Queries and returned snippets leave the computer for the configured Ollama cloud endpoint.

  1. Create an ollama.com account and obtain a Web Search API key.

    The free individual tier may be rate-limited, especially during bursts.

  2. Open Tools → Web search (cloud).

    Enable Web search and normally keep https://ollama.com/api/web_search.

  3. Paste the write-only key and select Save.

    The key is protected by DPAPI and never stored in settings.json. A custom endpoint receives both the key and queries.

  4. Select Test connection.

    The fixed-query test displays only duration and result count, never snippets.

  5. Enable Web search (web) (cloud) on the task.

    Use web.search with required query and optional maxResults (default 5, cap 10).

Results are untrusted external data. Titles and snippets are bounded, screened exactly once, and returned in one protectedResults envelope. Overflow is explicitly truncated or omitted. Source indexes and URLs are metadata; they disappear when Guardrails withholds the content. Disabled or failed screening still uses marked Base64—never raw text.
For multi-theme monitoring, also enable the Web Discovery group and use research.discover. sliding mode verifies dates locally after retrieval: it starts at two local calendar days and expands to four and seven days only when the minimumDocuments collection target is not met. This target never rejects eligible candidates: they are still delivered with insufficient=true. Old, future, and unverifiable-date pages are excluded; use freshnessWindow: "none" to allow undated content explicitly. Search, reading, and ranking remain deterministic; only the final selected titles and summaries cross Guardrails and are delivered in protectedResults. Requested translation runs only after a clean verdict, and its exact output is screened again. The windowHistory field makes the 2, 4, and 7-day budgets and outcomes auditable. Provider failures are not treated as zero results: searchStatus distinguishes available, degraded, unavailable, and rate-limited search. HTTP 429 stops the remaining queries and produces a diagnostic stating that source availability could not be determined. The editorial samples do not invent material when sources are scarce: zero candidates produce zero LinkedIn posts and no Sunday article. One source supports a focused article, two a limited cross-analysis, and three or more a full multi-source article. The complete discovery arguments are: required themes; optional freshnessWindow (sliding by default or none), sourceLanguage (en), language (empty), preferredDomains ([]), minimumDocuments (8, range 1–100), maxResultsPerQuery (10, range 1–10), and maxRetrievalsPerRun (40, range 1–100). Proposal memory adds previousProposalsDatabasePath (empty), previousProposalsLookbackMonths (6, range 1–60), usePreviousProposalUsedTag (false), and previousProposalsSemanticSimilarityThreshold (0.92, range 0.80–0.99). The daily LinkedIn sample also demonstrates optional proposal memory: sqlite.createProposalDatabase initializes a task-owned database, research.discover removes recent exact or semantic matches, and deterministic editorial aliases reserve, draft, prepare, and confirm the final output. When at least one candidate remains, the selector must produce at least one proposal; only proposals eliminated by the final anti-repetition filter lead to an empty report. This requires the sqlite group, a ReadWrite Authorized location, SqliteWrite, and the local Ollama Knowledge embedding provider.

Persistent conversation

Have a conversation in Direct Chat

Direct Chat keeps multiple local conversations and sends their context to the active provider. It starts without tools; you may explicitly enable tools for one conversation.

  1. Open Direct Chat, immediately after Tasks.

    A New chat conversation is created automatically when no history exists.

  2. Enter your message.

    Select Send or press Ctrl+Enter. Only one response can be generated at a time. After sending, the editor is intentionally cleared: Send becomes available again as soon as you enter a new message or add an attachment.

  3. Add an attachment when needed.

    Text, PDF, Word, and Excel files are read locally within controlled limits. PNG, JPEG, WebP, GIF, and BMP images are sent as images and require a vision-capable model. Attachment content is retained with the message so that its context can be restored when the conversation is reopened.

  4. Generate an image or audio only when the action is offered.

    Generate image and Generate audio appear only when the active provider explicitly declares that capability. Images provide preview, full-size opening, and saving. WAV audio provides play, stop, duration when available, and saving. Cloud content is labeled.

  5. Enable the agent only when needed.

    Below the conversation list, open Tools & permissions, check Enable tools for this conversation, select the required tool groups and sensitive permissions, then select Save permissions. Everything is disabled by default. For File system access, add each required folder under Authorized locations and choose read-only or read/write access. The permission list scrolls independently; the same sandbox, Guardrails, and connector rules as a task still apply.

  6. Turn useful work into a task.

    Create task copies the latest user prompt and this conversation’s permissions to a disabled task, then opens its editor. History and attachments are not copied: complete the schedule and review the task before enabling it.

  7. Follow the streamed response.

    Cancel stops generation. A canceled response remains identified as canceled; after an abrupt shutdown, an unfinished response is marked failed on the next start. A provider error or an incomplete streamed response is also marked Failed and receives an incident correlation id; you can continue the conversation after the failure.

  8. Return to or create a conversation.

    The left column sorts conversations by recent activity. New chat starts another conversation and Load older messages loads an earlier page. Drag the separator between the list and the conversation temporarily when you need more room for long authorized folder names.

  9. Copy a message when needed.

    Select the copy icon in a message bubble to place its text on the Windows clipboard.

  10. Delete only after review.

    Delete conversation asks for confirmation, then permanently removes the conversation, its messages, and all associated media.

When history approaches the declared context window, Direct Chat summarizes old turns and keeps at least the four latest user turns verbatim. The summary reduces only the context sent to the model: every original message remains in the database and the UI.
Conversations are stored as clear text in <FileSystem:RootPath>\.od-my-local-agent\data\direct-chat.db. This dedicated SQLite database is not the SQLite Tool, is unavailable to workflows, and is not protected by DPAPI. With a cloud provider, relevant context is sent to the configured endpoint. Media is limited by default to 25 MiB per item and 250 MiB per conversation. It is never copied automatically when a task is created.

  1. Open Tool tester.

    Select an alias from the list.

  2. Read the argument hint.

    The page displays the exact argument names expected by that alias.

  3. Enter a JSON object.

{
  "path": "."
}

Guided scenario 08

Enable an OpenAI-compatible provider

Cloud AI is an explicit choice. When selected, prompts and relevant context are sent to the configured endpoint.

  1. Open Settings → AI provider.

    Select OpenAI-compatible (cloud, opt-in) under Active provider, to the right of Test connection. Ollama settings remain saved, so you can switch back without re-entering them.

  2. Review the cloud warning.

    Confirm that the endpoint’s data and privacy policy is appropriate for the content you process.

  3. Enter Endpoint, Model, and Timeout.

    For OpenAI, the default endpoint is https://api.openai.com/v1. Compatible servers may use another URL. For OpenRouter, use https://openrouter.ai/api/v1 and copy the exact advertised model id, including a :free suffix when shown.

  4. Load the catalog when the provider exposes one.

    Refresh OpenAI-compatible models retrieves models exposed by the endpoint. The list remains editable: enter an id manually if the provider does not publish its catalog or if you already know the required id.

  5. Enter the key in Replace API key.

    The field becomes empty again after save because the key is stored with DPAPI and never displayed back.

  6. Select Save settings.

    The next test or task uses the new provider without restarting the application.

  7. Run Test connection.

    The test checks the currently selected provider, endpoint, and presence of the model in its catalog. Key, endpoint, and model errors are surfaced directly. There is no silent fallback to Ollama. A historical OpenRouter 404 came from an unsupported model-detail route; the test now uses the standard catalog endpoint.

Never add the API key manually to appsettings.json or settings.json. Use only the protected field in the application.

Automation

Tasks, prompts, and workflows

Understand how a task combines a prompt, deterministic workflow, generation settings, and authorizations.

Prompt only

The agent interprets the goal and may choose among allowed tools. This is flexible, but tool calling depends on the model.

Workflow

Steps follow their specified order by default; a decision may select another validated branch. This is recommended for unattended automation. When both exist, the workflow wins.

Route a workflow with a decision

Stage 29 adds flow.decision, which selects the next step without asking the model to perform the routing itself. A condition can inspect text, a number, or a property in a JSON object. A true result follows target; a false result follows next, or the next array item when next is omitted. 

[
  {
    "step": "flow.decision",
    "args": {
      "source": "{{classification.output}}",
      "path": "score",
      "operator": "greaterThanOrEqual",
      "value": 0.8,
      "target": "automaticReply",
      "fallback": "manualReview"
    },
    "next": "manualReview"
  },
  { "step": "ai.prompt", "id": "automaticReply",
    "args": { "prompt": "Prepare an answer." }, "next": "@end" },
  { "step": "ai.prompt", "id": "manualReview",
    "args": { "prompt": "Prepare a review note." } }
]

fallback is used only when the test cannot be evaluated—for example, when the source is not valid JSON, a property required by an operator other than exists is missing, or its type is incompatible. The workflow is rejected before save when a route destination is missing, a step is unreachable, or the routes form a cycle.

Get a JSON object from ai.prompt

Add responseSchema to an ai.prompt step to request a verifiable object response. The provider receives the schema and MyLocalAgent validates the JSON again before exposing the output to the workflow. A property can then be used as {{classification.output.category}}, or selected by a decision through its path argument. 

{
  "step": "ai.prompt",
  "id": "classification",
  "args": { "prompt": "Classify: {{task.prompt}}" },
  "responseSchema": {
    "type": "object",
    "properties": {
      "category": { "type": "string" },
      "score": { "type": "number" }
    },
    "required": ["category", "score"],
    "additionalProperties": false
  }
}
In this first stage, an ai.prompt step with responseSchema cannot also declare toolAliases. If the response is not strict JSON or does not satisfy the schema, the step fails according to its error policy.

Hierarchical generation settings

Settings defines Temperature, Top P, and Context window for every new call. A task can independently override Temperature and/or Top P through AI generation override. An object-form AI step can override each property again. Resolution is independent: AI step → task → Settings. Context window remains global and never appears in task or step JSON. 

{
  "generationOptions": {
    "temperature": 0.1
  },
  "workflow": [
    {
      "step": "ai.summarize",
      "id": "summary",
      "generationOptions": {
        "topP": 0.9
      }
    }
  ]
}

In this example, the step uses task Temperature 0.1 and step Top P 0.9. The Task editor's Use global default checkboxes are independent and show the effective value and provenance. Invalid input disables save. Prompt editor displays and uses these effective values—including unsaved changes—when running Test.

generationOptions is rejected on non-AI steps. Unknown fields, null or out-of-range values, and context/provider/endpoint/credential fields are rejected. Existing tasks without overrides remain valid; an empty object is omitted by canonical save.

Global model execution queue

In Settings → AI provider, Maximum simultaneous model requests limits concurrent requests from the application and every active Runner. The default is 1, which is recommended for local Ollama. Increase it only when the selected model and GPU are known to handle parallel generation. A request waits for its slot without consuming the provider timeout, and the wait can be canceled.

Temporary model selection and warm-up

Add "model": "model-name" to a task to use a model from the active provider for that task only. You can also add it to an object-form ai.prompt step: that value takes precedence and applies only to the step. It never changes the model in Settings, and the default model is restored even after an error or cancellation. 

{
  "model": "qwen3:32b",
  "workflow": [
    {
      "step": "ai.prompt",
      "id": "review",
      "args": { "prompt": "Review {{draft.output}}." },
      "model": "qwen3:32b"
    }
  ]
}

With Ollama, the temporary model is loaded and checked by a short warm-up immediately before execution. It must therefore be installed locally; if it is unavailable, the task or step fails without changing configuration. The model value must be a non-empty string and is allowed on a step only for ai.prompt. {{ModelName}} and {{ModelInfo}} show the model actually selected.

Model limitations. Temperature and Top P can behave slightly differently across providers and models. Changing both at once makes results harder to predict, and higher randomness can reduce structured-JSON or tool-selection reliability. Provider tokenization remains authoritative: Context window is a declared budget, not a universal exact counter, and cannot increase the model's physical capacity.

AI Workflow Helper

AI Helper turns an English description into exactly the workflow array shown in the editor. A loaded workflow becomes a deterministic, editable step-by-step description without a model call. You can edit it directly or submit one single-use refinement; no chat transcript is stored. The response streams through the provider selected in Settings and is accepted only after strict application validation. Generation, refinement, and their repairs always use Temperature 0 / Top P 1 with the global Context window.

Review every proposed missing tool group and literal absolute-directory authorization. Each starts unchecked. Dynamic or placeholder paths produce warnings without invented grants, and disabled Safety gates remain global warnings rather than automatic changes. Apply updates workflow, tools, and locations together in the editor; only Save task persists them. Undo assisted change is the single one-level undo shared by the AI Helper, the Tool catalog, and the Workflow prompt editor: it atomically restores the preceding workflow JSON, tool selections, and authorized locations until save, reload, navigation, or a later assisted application replaces the snapshot.

AI Explain validates locally before calling the model and explains steps, prompts, skills, placeholders, data flow, permissions, Safety gates, effects, and likely failures. Text is the dependable default. Rendered Markdown uses the same response in a restricted WebView2 document; a missing runtime keeps Text functional and exposes only a user-initiated official Microsoft download-page link. The complete window, including rendered Markdown, follows the currently selected Light or Dark theme. Explanation and its repairs use the same fixed internal Temperature 0 / Top P 1 policy, while the explanation still describes configured overrides and their effective provenance.

Privacy and limits. The helper never executes a step, invokes a tool or skill, reads referenced files, changes Safety, or persists assistant content. Selecting the cloud provider sends the description and workflow context to that configured endpoint. Valid JSON can still be semantically wrong, and static analysis cannot predict every runtime path or value. Cancel preserves incomplete output but cannot Apply it.

Tool catalog

Tool catalog is a searchable reference of every Tool Map alias, grouped by tool group, with its description, typed arguments, required/optional flags, examples, allowed values, and a placeholders tab. The dialog is entirely deterministic: it calls no model, tool, file, or network. Selecting an entry previews the exact snippet that will be inserted.

Insert applies the snippet and keeps the window open, so several steps can be accumulated in one session; Insert and close applies and closes; Close returns the accumulated result only when at least one effective change exists; Cancel discards the whole session. Closing with pending insertions asks for confirmation.

Insert and Insert and close apply to the Steps tab only and are therefore hidden on the Placeholders tab, where a placeholder is obtained with Copy to the clipboard. On that tab, Close is the only exit that keeps the insertions already accumulated.

The caret decides the position: inside an element inserts after it, between two elements inserts after the element on the left, before the first inserts at index 0, and after the last appends. Authorizations. A step whose tool group is not on the task whitelist produces a warning and an unchecked opt-in that you must accept explicitly. Workflow prompt editor

Edit workflow text lists eligible text arguments already present in the workflow, in declaration order, including ai.prompt.prompt, filesystem.write.content, and filesystem.powerShell.script. Short or format-constrained values are excluded. It edits only the selected text. No step is added, deleted, reordered, renamed, or re-typed, and no id, error policy, retry, generation option, or other argument is touched. Steps are keyed by position, so duplicate ids stay unambiguous.

For an ai.prompt entry, Model override (empty = task or Settings) selects a model for that step. In the Task Editor, clear Use model from Settings and enter Task model override to select a model for the entire task. Priority is: ai.prompt step model, then task model, then Settings model. This never switches provider: the active provider remains the Settings selection.

Prompts are edited with real line breaks. The working text is LF-canonical: CRLF and lone CR are normalized to LF and flagged, and nothing else about your whitespace changes. Because line breaks are written as \n escapes, each prompt still occupies one physical JSON line, and a round trip without an edit is lossless. Each row shows a single-line preview in which line feeds and tabs become visible markers.

includeContext is an independent option, enabled by default on a newly built ai.prompt step. It is never driven by the generic optional-arguments toggle. You can deliberately turn it off and reference a single prior-output placeholder to send only selected data. If a prompt already references prior output or accumulated context while includeContext is on, a duplication warning appears: it is informational, changes no value automatically, and does not block Apply.

Several prompts may be edited in one session. Apply validates everything, writes every change at once, and closes; it is enabled only when an effective change exists and no prompt is blank. Revert step restores a single entry and Cancel discards the session. This dialog deliberately has no Close command, and closing it with pending edits asks for confirmation.

Non-empty prompts and reformatting. An ai.prompt prompt that is missing, null, non-string, empty, or whitespace-only is rejected everywhere: Save, Validate, AI Helper validation, and prompt editor Apply. Every successful structured insertion or prompt application re-serializes the array canonically, so manual formatting of the workflow is normalized. SQLite

The sqlite group has four general aliases, two legacy aliases, and five specialized editorial aliases for one authorized local database file: sqlite.listObjects, sqlite.describeTable, sqlite.query, and sqlite.execute, plus sqlite.createProposalDatabase and sqlite.storeProposal, sqlite.reserveEditorialSelection, sqlite.prepareEditorialReport, sqlite.confirmEditorialExport, sqlite.importEditorialHistory, and sqlite.rebuildEditorialEmbeddings. Add sqlite to the task's allowed tools. Relative paths stay below FileSystem:RootPath; an absolute path needs an Authorized locations grant. The first three aliases require ReadOnly access. All write aliases require ReadWrite access and the task-owned SqliteWrite capability.

Use a database path, never a connection string, URI, network database, or :memory: database. A read never creates a file. A write creates a missing file only with "createIfMissing": true. Query and execute accept exactly one statement. Do not use transactions, ATTACH, PRAGMA, VACUUM, extensions, or internal sqlite_ objects.

Parameters are a JSON object of named scalar values. Keep the SQLite native prefix in every key (@, :, or $); values are bound safely and must not be concatenated into SQL.

Prepare the task and settings

  1. In the Task editor, select only sqlite in Tool whitelist.
  2. For reads, use a relative path below FileSystem:RootPath, or grant the absolute database file ReadOnly access in Authorized locations.
  3. For a write, grant ReadWrite access to the same location, then explicitly grant SqliteWrite under the task’s Sensitive operation permissions. These three conditions are independent.
  4. In Settings → SQLite, set the default and maximum rows, result and SQL character limits, BLOB limit, and timeout. Limits truncate a response; they do not guarantee a total number of rows or objects.

The Task editor’s Protect SQLite read results with Guardrails option is stored with each task. The identically named setting in Settings supplies only the initial value for new tasks and taskless tests (Tool tester and AI Playground); changing Settings does not modify an existing task.

The eleven aliases

  • sqlite.listObjects — databasePath, objectType (All, Table, View, Index, or Trigger), namePattern (a SQLite LIKE pattern), and maxResults. Returns visible schema objects in stable order, without their raw SQL.
  • sqlite.describeTable — databasePath and exact tableName. Returns columns, foreign keys, and indexes for that table or view; trigger bodies are never returned.
  • sqlite.query — databasePath, one read statement in sql, parameters, and maxRows. In this release, provide a database path: storageSpaceId is reserved and must be left unset.
  • sqlite.execute — databasePath, one modifying statement in sql, parameters, and createIfMissing. The call executes in an application-owned transaction.
  • sqlite.createProposalDatabase — required databasePath. Creates a missing file or validates/migrates the compatible editorial_proposals schema. It accepts no SQL, creates no parent directory, and is idempotent.
  • sqlite.storeProposal — required databasePath, title, and summary; optional sourceUrl and used (default false). It canonicalizes the URL, calculates the local title + summary embedding, and atomically inserts or updates the deterministic proposal identity. It accepts no SQL, vector, model, dimension, or timestamp.
  • sqlite.reserveEditorialSelection — receives the exact Discover output, the structured selection, and {{workflow.runId}}. It verifies sources, reserves only confirmed novelty, and reports rejections.
  • sqlite.prepareEditorialReport — assembles deterministic Markdown from approved reservations and exactly corresponding draft blocks.
  • sqlite.confirmEditorialExport — verifies that the written file exactly matches the prepared report fingerprint before marking it exported.
  • sqlite.importEditorialHistory — inventories by default, then imports historical Markdown reports with dryRun=false while preserving their dates.
  • sqlite.rebuildEditorialEmbeddings — inventories by default, then rebuilds proposal-memory embeddings with dryRun=false and the configured local model.

Reads must produce results (SELECT, WITH, VALUES, or EXPLAIN). Writes include INSERT, UPDATE, DELETE, CREATE, ALTER, and DROP, but not RETURNING. Exactly one statement is allowed, with at most one final semicolon and trailing comments. Parameters must exactly match the SQL named parameters; objects, arrays, positional parameters, and non-finite values are rejected.

{

}

Proposal-memory syntax

Proposal memory is an ordinary task-owned database, not application-owned storage and not a publication register. The directory must be ReadWrite because the workflow initializes and records proposals; research.discover itself opens the database ReadOnly. Use the local Ollama Knowledge embedding provider. An OpenAI-compatible embedding provider is rejected before generation so proposal vectors never leave the machine.

{
  "step": "sqlite.createProposalDatabase",
  "id": "ensureProposalMemory",
  "args": {
    "databasePath": "C:\\EditorialWatch\\editorial-proposals.db"

  "step": "research.discover",
  "id": "discover",

    "themes": "[{\"terms\":[\".NET\",\"C#\"]}]",

previousProposalsDatabasePath is optional and empty by default; omission disables memory. previousProposalsLookbackMonths defaults to 6 and accepts 1–60. usePreviousProposalUsedTag defaults to false: all recent rows are still excluded regardless of used; when true, old rows with used = 1 are excluded as well. previousProposalsSemanticSimilarityThreshold defaults to 0.92 and accepts 0.80–0.99 inclusively. Missing, inaccessible, malformed, or incompatible databases fail the step.

Filtering runs after ordinary URL deduplication, date eligibility, and ranking. It rejects normalized title matches, then canonical source-URL matches, then compatible local embeddings at or above the threshold. The daily DB workflow does not expose sqlite.storeProposal to the model. After Discover, a flow.decision examines candidateCount: zero creates an empty reservation; otherwise the selection schema requires 1 to 3 proposals and two further attempts are made for an invalid response. sqlite.reserveEditorialSelection is then the final anti-repetition arbiter. Drafting receives only approved reservations; sqlite.prepareEditorialReport and sqlite.confirmEditorialExport ensure that exported Markdown is exactly the content that was reserved. Use {{workflow.runId}} to link all steps of one execution.

The creation result exposes databaseCreated, tableCreated, and schemaCompatible. Reservation exposes approved and rejected subjects, the prepared report exposes its fingerprint, and confirmation returns the path and the same fingerprint. The table contract contains id, title, summary, nullable source_url, UTC created_at_utc, Boolean-integer used, unique proposal_key, embedding_model, embedding_dimension, and BLOB embedding.

Read results and data protection

The three read aliases return an envelope with either data or protectedData, never both, together with contentEncoding, screened, sqliteGuardrailsEnabled, trust fields, screeningChunkCount, and resultCharacterCount. For a clean read, data contains the logical result. A query exposes ordered columns (name, ordinal, declaredType) and array rows so order and duplicate column names are preserved. Object and description responses also signal truncation; query supplies hasMoreRows, truncated, and resultTruncated.

BLOBs are described by $type, byteLength, base64, and omitted. When the BLOB limit is zero or exceeded, Base64 content is omitted. Results stop at object or row limits and then at the complete-size limit, so missing data must not be treated as proof that it does not exist.

Settings → SQLite controls the default and maximum rows, result characters, BLOB bytes, SQL characters, and busy timeout. A task stores its own Protect SQLite read results with Guardrails choice; the setting for new tasks is copied only at task creation. Guardrails-protected read data is protected or withheld if screening cannot safely complete. Start with disposable, non-sensitive data. With an OpenAI-compatible provider, this screening can send bounded database content to the configured cloud provider. Clearing this task option sends database data as plaintext to the workflow or later model. Guardrails is probabilistic and Base64 is defense in depth, not isolation or encryption.

This SQLite capability provides no encryption, backup or restore, migration batch, automatic WAL tuning, remote or network database, ATTACH, extension, or caller-controlled transaction. The timeout handles lock waiting, not a CPU deadline; Runner cancellation interrupts the native operation. An allowed statement can still modify many rows or schema objects: no SQL filter can prove business intent. Start with disposable, non-sensitive data.

Prompt-injection risk reduction

Understand the content trust filter

Gmail reads and http.get / http.getText responses are deterministically compacted before direct LLM calls with no tools, skills, or agent loop. This probabilistic control does not replace Safety gates, tool whitelists, the filesystem sandbox, or the HTTP host allowlist.

Score/statusModel delivery
Clean, 80–100 by defaultMarked plaintext inside UNTRUSTED-EXTERNAL-DATA delimiters.
Caution, 50–79Marked UTF-8 Base64 inside UNTRUSTED-EXTERNAL-DATA-BASE64 delimiters.
Low, 0–49Content is withheld and replaced by a score marker.
ScreeningDisabled / FailedMarked Base64 for normal-size content.
Base64 is neither encryption nor a security boundary. A model can decode it and must still treat the decoded text only as data, never instructions.

Compact projections and batches

Gmail and HTTP discard boilerplate and over-budget suffixes before any model call. Every omission is represented by character-count metadata or an application marker. Compaction is a minimization boundary, not evidence that omitted text was safe. Gmail items are processed in stable batches of at most 12 items and three eligible phases; a failed batch is not replayed item by item.

  • Gmail success delivers projected From, To, Subject, and Received plus a protected factual summary. Snippet, Body, quoted history, and omitted suffixes never reach workflow context.
  • http.getText delivers only a protected summary of readable compact text. http.get delivers one protected media-aware compact prefix and is never summarized.
  • A positive Gmail limit processes only the first N messages with explicit counts and a warning; 0 is unlimited.
Generated summaries can omit details. Review the original message in Gmail or the original source URL whenever completeness matters.

Trust filter page

Paste external text, optionally select Return Base64, then select Screen. The page separates trust status from processing status and shows score, provider, latency, lengths, protected preview, and validated verbatim indicators. Indicator text stays on this human page; Gmail/HTTP/Web Search tool output exposes only the count.

Settings, privacy, and limitations

Settings → General → Guardrails controls thresholds, size limits, reduction, timeout, the 24-hour in-memory cache, and Gmail limit. Turning off Use LLM guardrails processing does not turn off protection: compact Gmail/HTTP review blocks use marked Base64 when screening is unavailable.

With OpenAI-compatible selected, screened Gmail/HTTP/Web Search content leaves the machine. Only the compact projection and generated summary are sent; omitted source text is discarded first. Do not use real private mail in a cloud test without explicit authorization.

False positives and false negatives remain possible, especially for encoded or obfuscated attacks. Dropbox, local files, Calendar, Gmail attachments, outbound content, and HTTP POST responses are out of scope.

Archives, Office documents, and PDF

Archives, Word documents, Spreadsheets, and PDF documents are independent and unchecked for a new task. A group never grants a path, and a path grant never enables a group. Grant each input ReadOnly and each output ReadWrite. Archive extraction, creation, and addition also require the task-owned ArchiveWrite capability; it grants neither a group nor a path.

Untrusted data: archive names, document text, sheet names, cells, and PDF metadata may contain misleading instructions. Mandatory limits are applied before content reaches an agent or workflow.

Formats and boundaries

Read/extract formats are ZIP, 7z, RAR, TAR, TAR.GZ/TGZ, TAR.BZ2/TBZ2, TAR.LZ, TAR.XZ/TXZ, TAR.ZST/TZST, GZIP, BZIP2, LZIP, XZ, and Zstandard, with extension plus content validation. Only ZIP is writable. DOCX, XLS/XLSX/XLSB stored values, and PDF metadata/text are read-only and locally parsed; files are never opened in a desktop application.

Shipped ceilings: 100 MiB input; 10,000 archive entries; 250 MiB per extracted entry; 1 GiB total extraction; ratio 200; 1,000 listed entries; 64,000 characters; 1,000 rows; 256 columns; 25,000 cells; 100 PDF pages. Settings may adjust them only inside validated ranges; no value disables a limit.

1. Extract one ZIP entry

Enable Archives, grant work/in.zip ReadOnly and work/output/readme.txt ReadWrite, grant ArchiveWrite, then use:

{ "id": "extract-one", "tool": "archive.extract", "arguments": {
  "archivePath": "work/in.zip", "entryPath": "docs/readme.txt",
  "destinationPath": "work/output/readme.txt", "overwrite": false
} }

2. Extract a complete archive

The destination parent must exist, but work/output/package must not. The complete result is staged and renamed only after validation.

{ "id": "extract-all", "tool": "archive.extractAll", "arguments": {
  "archivePath": "work/in.7z", "destinationDirectory": "work/output/package"
} }

3. Create a ZIP, then add a file

Creation defaults to deflate/balanced; overwrite defaults false. The second step demonstrates store, for which compressionLevel must be omitted. Deflate levels are exactly fast, balanced, and smallest.

[
  { "id": "create", "tool": "archive.createZip", "arguments": {
    "archivePath": "work/output/bundle.zip", "sourcePath": "work/input/first.txt"
  } },
  { "id": "add", "tool": "archive.addToZip", "arguments": {
    "archivePath": "work/output/bundle.zip", "sourcePath": "work/input/second.txt",
    "entryPath": "documents/second.txt", "overwriteEntry": false, "compressionMethod": "store"
  } }
]

ZIP creation/addition builds and validates a complete temporary sibling before replacement. The old ZIP survives construction, parser, limit, or cancellation failure.

4. Read a DOCX

{ "id": "read-docx", "tool": "document.readDocx", "arguments": {
  "documentPath": "work/docs/notes.docx", "maxCharacters": 12000
} }

Body paragraphs, tabs, breaks, tables, hyperlink display text, and current inserted text are included. Headers, footers, comments, notes, text boxes, images/alt text, deleted revisions, embedded packages, custom XML, and external relationships are omitted. The source is never written.

5. List sheets and read a bounded range

[
  { "id": "sheets", "tool": "spreadsheet.listSheets", "arguments": {
    "workbookPath": "work/data/report.xlsx"
  } },
  { "id": "range", "tool": "spreadsheet.readRange", "arguments": {
    "workbookPath": "work/data/report.xlsx", "sheetName": "Summary",
    "startRow": 2, "startColumn": 1, "maxRows": 100, "maxColumns": 8
  } }
]

Cells use stable type markers. Formulas, macros, links, queries, and connections are never run or refreshed; only stored/cached values are returned, so formula results may be stale. The workbook is never written.

6. Read selected PDF pages

[
  { "id": "pdf-info", "tool": "pdf.getInfo", "arguments": {
    "pdfPath": "work/docs/report.pdf"
  } },
  { "id": "pdf-pages", "tool": "pdf.readText", "arguments": {
    "pdfPath": "work/docs/report.pdf", "startPage": 3,
    "maxPages": 5, "maxCharacters": 16000
  } }
]

This is layout-aware text extraction, not OCR. An image-only page returns empty text and hasExtractableText: false. Columns, ligatures, scans, and unusual fonts can make order incomplete. No rendering, editing, signing, form filling, attachment extraction, JavaScript, or link fetch occurs.

Embedded Knowledge and RAG

Open Knowledge to import TXT, Markdown, HTML, DOCX, or text-based PDF documents. HTML is converted automatically to structured Markdown before indexing. Files are copied below the private application workspace, extracted, split into deterministic chunks, and embedded locally. The picker accepts multiple files: tags are shared, names come from file names, and descriptions remain empty. Progress identifies the current file and ingestion phase. A duplicate or failure does not stop the rest of the batch, and the final summary distinguishes imports, duplicates, and failures. Canceling preserves completed documents without adding a partial document for the current file. OCR is not provided, image-only PDFs are unsupported, and Knowledge data is not encrypted at rest.

Configure and test the independent provider and model under Settings → Knowledge embeddings. Ollama defaults to embeddinggemma:300m. Changing the model or chunking contract requires Reindex library; the previous complete index remains active if rebuilding fails or is canceled.

Access is denied by default. Enable the ordinary knowledge group on a task or Direct Chat conversation, then select explicit library tags. An empty scope grants no document. An ai.prompt workflow step may declare the exact knowledge.search alias and may narrow, but never broaden, the task tags.

Hybrid search combines exact-term matching and semantic retrieval, then favors complementary excerpts. It may add immediately adjacent context from the same section and page within the global limits under Settings → Knowledge embeddings. Those settings affect retrieval behavior for the entire library; they do not change access rights. An exact-term match does not prove that a document is trustworthy or complete. Retrieval occurs only when the agent calls the tool; excerpts are untrusted data and are never injected automatically.

Per-task sensitive permissions

Sensitive operations are denied by default. There is no global Safety switch. A task must explicitly grant the required capability in addition to its tool-group whitelist and file-system access rules. PowerShell and Shell Execute are separate permissions. Legacy tasks without capabilities receive no sensitive permission.

The Edit workflow text dialog edits long AI prompts and PowerShell scripts atomically while preserving step identity, order, type, and unrelated arguments.

Workflow step editor

Place the caret in valid workflow JSON, then choose Insert before, Insert after, Edit step, or Delete step. The form is generated from the Tool Map. An existing step cannot be converted to another tool: delete it and insert a replacement.

For ai.prompt and filesystem.write, Repeat for each item adds a selector for an earlier array. The editor also warns when a repeated write path has no {{foreach.*}} placeholder and would therefore replace the same file each time.

Delete warns when a later step uses that step’s output placeholder. Tool groups and sensitive capabilities are proposed unchecked and are changed only when you explicitly accept them. Changes affect the task draft; choose Save task to persist them.

In an ai.prompt step, select exact prompt tools from the catalog list. Model, Temperature, Top P, and reasoning can inherit independently. Knowledge scope appears only when knowledge.search is selected: inherit the task scope or narrow it to one or more currently authorized tags. Absolute local paths may create unchecked directory proposals and root, UNC, or broader-scope warnings. Cancel or close discards the complete working copy after confirmation; Apply validates the complete provisional task and never runs a tool.
