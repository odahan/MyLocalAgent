Getting started

Installation and prerequisites

OD.MyLocalAgent runs on 64-bit Windows 10 or Windows 11. Published builds are self-contained and do not require a separately installed .NET runtime.

Essential requirements

  • Windows 10 or Windows 11 under your normal user account.
  • Ollama installed with its service running.
  • At least one local model, normally gemma4:12b.
  • Google and Dropbox accounts only when those connectors are needed.

Published layout

The UI and headless runner are intentionally separate. Windows Task Scheduler starts the runner.

%LOCALAPPDATA%\Programs\OD.MyLocalAgent\
├── UI\OD.MyLocalAgent.UI.exe
└── Runner\OD.MyLocalAgent.Runner.exe

Prepare Ollama

In PowerShell, check Ollama and install the recommended model:

ollama --version
ollama pull gemma4:12b
ollama list
The model tag shown by ollama list must exactly match the tag selected in the application. gemma4:12b and gemma4:latest are different identifiers.

Publish from the repository

If you have the source repository, open PowerShell at its root and run:

.\scripts\publish.ps1

Then start %LOCALAPPDATA%\Programs\OD.MyLocalAgent\UI\OD.MyLocalAgent.UI.exe.

Getting started

First start: the checklist

Perform these checks in order. They isolate model, runner, and permission problems before you create more complex tasks.

  1. Open Settings.

    Keep Ollama (local, default) selected for the first test.

  2. Check the endpoint and model.

    The usual local endpoint is http://localhost:11434. Select an installed model.

  3. Set File-system root path.

    For example, C:\OD.MyLocalAgent. File tools are confined to this directory.

  4. Leave Runner path empty.

    In the standard installation, the application locates the sibling runner automatically.

  5. Locate the folder and shortcut utilities.

    The copy icons place the reports and executable directories on the clipboard separately. Create desktop shortcut creates or refreshes the UI shortcut on the Windows desktop.

  6. Select Save settings.

    Wait for the message confirming that settings were saved and reloaded.

  7. Run Test connection.

    The result should report a healthy provider and display latency.

Allow sending email, Allow file deletion, and Allow HTTP POST are disabled by default. Do not enable them preemptively; wait until a reviewed workflow actually needs them.

Guided scenario 01

Configure Ollama and select a model

This scenario configures the default local provider and verifies that the selected model is installed on the target Ollama endpoint.

  1. Open Settings → AI provider.

    Select Ollama (local, default).

  2. Enter the endpoint.

    Normally use http://localhost:11434. For an approved remote Ollama server, enter its HTTP or HTTPS URL.

  3. Select Refresh models.

    The list is loaded from the entered endpoint. A failure is reported without switching to a cloud provider.

  4. Choose the model in the combo box.

    The field remains editable, but a manually entered tag must still exist in Ollama.

  5. Review AI generation defaults.

    Initial values are Temperature 0.2, Top P 1, and Context window 8192. Valid ranges are 0–2, greater than 0 through 1, and 1024–2000000. Tune Temperature or Top P first instead of changing both.

  6. Keep a suitable timeout.

    The default 300 seconds allows for a slow first token from a large local model.

  7. Save, then test.

    Select Save settings, followed by Test connection.

A healthy result means both that the endpoint is reachable and that the configured model appears in the installed-model list.
Context window is the declared total budget—messages, agent/tool context, and response—not an output-token limit. Ollama receives it through native num_ctx. An OpenAI-compatible provider remains authoritative for its fixed capacity; no unsupported request field is invented.

Guided scenario 02

Create a fully local first task

This task creates a directory, writes a file, and reads it back. It requires no cloud account and validates storage, workflow execution, the runner, and reports.

  1. Prepare the allowed directory.

    In Settings, set File-system root path to a path such as C:\OD.MyLocalAgent, then save.

  2. Open Tasks and select New.

    The task editor opens.

  3. Enter the identity.

    Id: first-local-task · Name: First local task. The id accepts lowercase letters, digits, and hyphens.

  4. Add a descriptive prompt.

    For example: “Verify the local filesystem workflow and report the result.”

  5. Choose a schedule.

    Under Quick schedule, choose Every day at 09:00. Check the next three occurrences.

  6. Allow only File system.

    Leave every other group cleared in Tool whitelist.

  7. Paste the following into Workflow JSON.

    The editor expects the array of steps, not the complete task object.

[
  {
    "step": "filesystem.createDirectory",
    "id": "createWelcomeDirectory",
    "args": {
      "path": "welcome"
    }
  },
  {
    "step": "filesystem.write",
    "id": "writeWelcomeFile",
    "args": {
      "path": "welcome/hello.txt",
      "content": "OD.MyLocalAgent completed {{task.id}}."
    }
  },
  {
    "step": "filesystem.read",
    "id": "readWelcomeFile",
    "args": {
      "path": "welcome/hello.txt"
    }
  }
]
  1. Keep the task enabled and save it.

    Select Save task. Syntax, aliases, arguments, ids, and whitelist access are validated. If the definition is incomplete or invalid, a dialog explains that no changes were saved. Back asks for confirmation before discarding a changed draft.

  2. Run it immediately.

    Return to Tasks, select the row, and choose Run now.

  3. Check the result.

    Runner output should confirm success. The file welcome\hello.txt appears under the configured root.

Why this task is safe: it has only the filesystem group, every path is relative to the allowed root, and it does not request deletion.

Guided scenario 03

Test a prompt, then run the real task

Prompt testing supports fast iteration with streaming output. Run now then uses the same runner as Windows scheduling.

  1. Select a task in Tasks.

    Choose Prompt.

  2. Edit Agent prompt.

    State the expected outcome, output format, language, and limits.

  3. Select Save prompt.

    The text is written back to the task definition.

  4. Run Test the prompt.

    The answer streams into Streamed agent output. The task tool whitelist applies.

  5. Adjust and repeat if needed.

    Use Cancel to stop a long generation.

  6. Return to Tasks and choose Run now.

    If the task has a workflow, the workflow wins. Otherwise, the runner executes the prompt with the allowed tools.

A prompt test is not a workflow test. Test the prompt tests the agent and whitelist. Run now executes the actual task path and writes the normal report.

Guided scenario 04

Connect Gmail and Google Calendar

Google authorization is interactive. Complete it in the UI under the same Windows account that will run scheduled tasks.

Prepare Google Cloud

  1. Create or select a Google Cloud project.

    Enable Gmail API and Google Calendar API.

  2. Configure the OAuth consent screen.

    Add the intended account as a test user while the app remains in testing.

  3. Create an OAuth client of type Desktop app.

    Copy its Client ID and Client Secret.

  4. Close OD.MyLocalAgent and update settings.json.

    Preserve the file’s other sections and add or update the following section.

{
  "Google": {
    "ClientId": "YOUR_DESKTOP_CLIENT_ID",
    "ClientSecret": "YOUR_DESKTOP_CLIENT_SECRET"
  }
}

The file is %LOCALAPPDATA%\OD.MyLocalAgent\settings.json.

Authorize in the application

  1. Restart the application and open Tools.

    Google Workspace should report that OAuth client configuration is available.

  2. Select Connect.

    Complete consent in the browser with the intended Google account.

  3. Return to the application and refresh status.

    Use Refresh status if needed.

  4. Test Gmail and Calendar separately.

    Each Test connection performs a read-only check and displays latency.

  5. Enable only Gmail and/or Calendar on the task.

    OAuth consent does not replace the per-task whitelist.

Reading mail and sending mail are separate capabilities. gmail.send stays blocked until Allow sending email is explicitly enabled in Settings.

Guided scenario 05

Connect Dropbox

Dropbox values are write-only in the UI and protected with DPAPI for the current Windows user.

  1. Create an app in Dropbox App Console.

    Choose the narrowest access type possible, preferably an app folder.

  2. Enable only required permissions.

    Metadata read, content read, and content write as needed by the selected aliases.

  3. Obtain credentials.

    Use either an access token, or a refresh token together with the app key.

  4. Open Tools → Dropbox.

    Enter the replacement values in the provided fields.

  5. Select Save credentials.

    Secrets are encrypted for the current user and never written to settings.json.

  6. Run Test connection.

    The test uses a read-only operation.

  7. Add Dropbox to the relevant task.

    Check Dropbox in the whitelist and use a dropbox.* alias in the workflow.

Guided scenario 06 · Cloud opt-in

Enable guarded Ollama Web Search

Web Search is disabled on a fresh install. Queries and returned snippets leave the computer for the configured Ollama cloud endpoint.

  1. Create an ollama.com account and obtain a Web Search API key.

    The free individual tier may be rate-limited, especially during bursts.

  2. Open Tools → Web search (cloud).

    Enable Web search and normally keep https://ollama.com/api/web_search.

  3. Paste the write-only key and select Save.

    The key is protected by DPAPI and never stored in settings.json. A custom endpoint receives both the key and queries.

  4. Select Test connection.

    The fixed-query test displays only duration and result count, never snippets.

  5. Enable Web search (web) (cloud) on the task.

    Use web.search with required query and optional maxResults (default 5, cap 10).

Results are untrusted external data. Titles and snippets are bounded, screened exactly once, and returned in one protectedResults envelope. Overflow is explicitly truncated or omitted. Source indexes and URLs are metadata; they disappear when Guardrails withholds the content. Disabled or failed screening still uses marked Base64—never raw text.

Guided scenario 07

Explore a prompt in the AI playground

The playground is designed for free-form experiments. Its default mode calls the provider directly; tools and skills each require an explicit opt-in.

  1. Open AI playground.

    The badge shows the active provider, model, and global effective policy used for that generation.

  2. Select Check health.

    Resolve an unavailable endpoint or model before generating.

  3. Enter a prompt.

    With both boxes cleared, generation is a raw completion without tools or skills.

  4. Select only the capabilities you need.

    Check Allow Tools and/or Allow Skills.

  5. Select Generate.

    The answer streams into the response pane. Cancel stops it.

Allow ToolsAllow SkillsExecution mode
NoNoRaw provider completion.
YesNoAgent with all six tool groups.
NoYesAgent with summarize, extract action items, and classify email.
YesYesAgent with both tools and built-in skills.
Allow Tools enables every tool group for that interactive test. Global protections still apply: the filesystem sandbox, HTTP allowlist, connector configuration, and Safety settings.

Guided scenario 07

Test one tool in isolation

Tool tester invokes one alias with explicit JSON arguments. It is the fastest way to isolate a connector or safety issue.

  1. Open Tool tester.

    Select an alias from the list.

  2. Read the argument hint.

    The page displays the exact argument names expected by that alias.

  3. Enter a JSON object.

    To list the sandbox root, choose filesystem.list and use:

{
  "path": "."
}
  1. Select Run tool.

    The formatted result and execution time appear in the result pane.

  2. If blocked, read the named setting.

    A protected operation tells you exactly which Safety option it needs. Enable it only after review.

Start with aliases that have no destructive side effect: filesystem.list, filesystem.read, gmail.readUnread, calendar.today, or dropbox.list.

Guided scenario 08

Enable an OpenAI-compatible provider

Cloud AI is an explicit choice. When selected, prompts and relevant context are sent to the configured endpoint.

  1. Open Settings → AI provider.

    Select OpenAI-compatible (cloud, opt-in).

  2. Review the cloud warning.

    Confirm that the endpoint’s data and privacy policy is appropriate for the content you process.

  3. Enter Endpoint, Model, and Timeout.

    For OpenAI, the default endpoint is https://api.openai.com/v1. Compatible servers may use another URL.

  4. Enter the key in Replace API key.

    The field becomes empty again after save because the key is stored with DPAPI and never displayed back.

  5. Select Save settings.

    The next test or task uses the new provider without restarting the application.

  6. Run Test connection.

    Key, endpoint, and model errors are surfaced directly. There is no silent fallback to Ollama.

Never add the API key manually to appsettings.json or settings.json. Use only the protected field in the application.

Reference

Tasks, prompts, and workflows

A task combines identity, schedule, prompt, tool whitelist, and optionally a deterministic workflow.

Prompt only

The agent interprets the goal and may choose among allowed tools. This is flexible, but tool calling depends on the model.

Workflow

Steps run in the specified order. This is recommended for unattended automation. When both exist, the workflow wins.

Hierarchical generation settings

Settings defines Temperature, Top P, and Context window for every new call. A task can independently override Temperature and/or Top P through AI generation override. An object-form AI step can override each property again. Resolution is independent: AI step → task → Settings. Context window remains global and never appears in task or step JSON. 

{
  "generationOptions": {
    "temperature": 0.1
  },
  "workflow": [
    {
      "step": "ai.summarize",
      "id": "summary",
      "generationOptions": {
        "topP": 0.9
      }
    }
  ]
}

In this example, the step uses task Temperature 0.1 and step Top P 0.9. The Task editor's Use global default checkboxes are independent and show the effective value and provenance. Invalid input disables save. Prompt editor displays and uses these effective values—including unsaved changes—when running Test.

generationOptions is rejected on non-AI steps. Unknown fields, null or out-of-range values, and context/provider/model/endpoint/credential fields are rejected. Existing tasks without overrides remain valid; an empty object is omitted by canonical save.
Model limitations. Temperature and Top P can behave slightly differently across providers and models. Changing both at once makes results harder to predict, and higher randomness can reduce structured-JSON or tool-selection reliability. Provider tokenization remains authoritative: Context window is a declared budget, not a universal exact counter, and cannot increase the model's physical capacity.

AI Workflow Helper

AI Helper turns an English description into exactly the workflow array shown in the editor. A loaded workflow becomes a deterministic, editable step-by-step description without a model call. You can edit it directly or submit one single-use refinement; no chat transcript is stored. The response streams through the provider selected in Settings and is accepted only after strict application validation. Generation, refinement, and their repairs always use Temperature 0 / Top P 1 with the global Context window.

Review every proposed missing tool group and literal absolute-directory authorization. Each starts unchecked. Dynamic or placeholder paths produce warnings without invented grants, and disabled Safety gates remain global warnings rather than automatic changes. Apply updates workflow, tools, and locations together in the editor; only Save task persists them. Undo AI changes restores the prior editor values until save, reload, navigation, or a later Apply.

AI Explain validates locally before calling the model and explains steps, prompts, skills, placeholders, data flow, permissions, Safety gates, effects, and likely failures. Text is the dependable default. Rendered Markdown uses the same response in a restricted WebView2 document; a missing runtime keeps Text functional and exposes only a user-initiated official Microsoft download-page link. The complete window, including rendered Markdown, follows the currently selected Light or Dark theme. Explanation and its repairs use the same fixed internal Temperature 0 / Top P 1 policy, while the explanation still describes configured overrides and their effective provenance.

Privacy and limits. The helper never executes a step, invokes a tool or skill, reads referenced files, changes Safety, or persists assistant content. Selecting the cloud provider sends the description and workflow context to that configured endpoint. Valid JSON can still be semantically wrong, and static analysis cannot predict every runtime path or value. Cancel preserves incomplete output but cannot Apply it.

Task shape

{
  "id": "daily-mail-summary",
  "name": "Daily mail summary",
  "schedule": "0 7 * * *",
  "prompt": "Summarize today's important messages.",
  "tools": ["gmail", "filesystem"],
  "fileSystemAccess": [],
  "generationOptions": {
    "temperature": 0.1
  },
  "workflow": [
    "gmail.readToday",
    {
      "step": "ai.summarize",
      "id": "summary",
      "generationOptions": {
        "topP": 0.9
      }
    },
    {
      "step": "filesystem.write",
      "args": {
        "path": "reports/mail-summary.md",
        "content": "{{summary.output.text}}"
      }
    }
  ],
  "enabled": true,
  "errorPolicy": "StopOnError"
}

Important rules

  • Ids follow [a-z0-9-]+ and are immutable after creation.
  • The prompt may be empty only when the workflow contains at least one step.
  • A tool alias requires its group in Tool whitelist.
  • An ai.* skill is always allowed in workflows.
  • Relative filesystem paths stay beneath the configured RootPath.
  • Absolute paths require a matching task-owned Authorized location.

Authorized locations

The task editor can grant this task access to additional absolute directories without creating a global catalog. Each rule includes all descendants and is either ReadOnly or ReadWrite. An empty array grants no absolute path. Windows permissions remain authoritative. 

"fileSystemAccess": [
  {
    "path": "D:\\Production\\Incoming",
    "access": "ReadOnly"
  },
  {
    "path": "E:\\Archives\\Daily",
    "access": "ReadWrite"
  }
]

Outputs and placeholders

String-form steps have no explicit arguments. Object-form steps accept step, id, args, and error behavior. Placeholders are replaced immediately before each step runs.

PlaceholderValue
{{task.id}}Task id.
{{task.name}}Task name.
{{task.prompt}}Saved task prompt.
{{previous.output}}Output of the previous step.
{{stepId.output}}Output of a named step.
{{stepId.output.property}}Property selected from a JSON step output; array indexes such as items[0].name are supported.
{{workflow.context}}JSON snapshot of every successful output accumulated so far.
{{Today}}Current local date as yyyy-MM-dd.
{{Today[format]}}Current local date using the requested format, for example {{Today[YYYY]}} or {{Today[yyyyMMdd]}}.
{{Now}}Current local date and time as yyyy-MM-ddTHH:mm:sszzz.
{{Now[format]}}Current local date and time using the requested format, for example {{Now[hhmmss]}}.

The delimiters are exactly two opening braces and two closing braces: {{placeholder}}. A placeholder may appear alone or inside surrounding text in any string value under args. Resolution is recursive in objects and arrays, but does not apply to JSON property names, numbers, or booleans. Names and selected JSON properties are case-insensitive. There is no literal-brace escape syntax: every {{...}} sequence is interpreted and an unknown name fails the step.

Structured selectors start after .output. A dot selects an object property and [0] selects a zero-based array item. For example, {{files.output.entries[0].name}} selects the first file name. A missing property, invalid index, or selector applied to plain text fails the step instead of silently inserting an empty value.

Date and time values use the Windows local time zone. Brackets contain .NET custom date/time format text. The filename-friendly aliases YYYY, YY, DD, and hh mean yyyy, yy, dd, and 24-hour HH. Use formats without / or : in Windows file names. 

{
  "path": "reports/{{Today[YYYY]}}/triage-{{Now[yyyyMMdd-hhmmss]}}.md",
  "content": "{{triage.output.text}}"
}

Renaming a file and changing its extension

filesystem.rename accepts a leaf name only and keeps the current directory. filesystem.setExtension keeps the base name and accepts an extension with or without its leading period. Both require read-write authorization, refuse an existing destination, and return a JSON to path that the next step can reuse. 

[
  {
    "step": "filesystem.rename",
    "id": "rename",
    "args": {
      "path": "incoming/report.tmp",
      "newName": "report-{{Today[yyyyMMdd]}}.tmp"
    }
  },
  {
    "step": "filesystem.setExtension",
    "args": {
      "path": "{{rename.output.to}}",
      "extension": ".md"
    }
  }
]

Using action extraction and email classification without loops

Both skills are tool-less LLM calls. If args.text is omitted, they receive the complete previous-step output; when they are first, they receive the task prompt. An explicit text value takes precedence. They can therefore process the complete batch returned by gmail.readUnread in one call—no workflow loop is required. Their output is {"text":"..."}; use {{stepId.output.text}} to insert only the generated Markdown.

ai.classifyEmail creates one table row per identifiable message with Message, Category, Reason, and Deadline. It produces an aggregate report only: it does not branch the workflow and cannot execute a different operation for each category. 

[
  "gmail.readUnread",
  { "step": "ai.classifyEmail", "id": "triage" },
  {
    "step": "filesystem.write",
    "args": {
      "path": "reports/mail-triage-{{Today[yyyyMMdd]}}.md",
      "content": "{{triage.output.text}}"
    }
  }
]

ai.extractActionItems uses the same batch pattern. It returns Markdown checklist rows containing only explicit actions and writes Not stated for an absent owner, due date, or source. If none exist, it returns exactly No explicit action items. 

[
  "gmail.readUnread",
  { "step": "ai.extractActionItems", "id": "actions" },
  {
    "step": "filesystem.write",
    "args": {
      "path": "reports/actions-{{Now[yyyyMMdd-HHmmss]}}.md",
      "content": "{{actions.output.text}}"
    }
  }
]

Scheduling and cron format

The editor provides plain-language presets. Advanced schedules remain editable, and the preview computes the next three occurrences in the local Windows time zone.

The five fields

minute   hour   day-of-month   month   day-of-week
 0-59    0-23       1-31       1-12       0-6

* means every value, */n an interval, commas a list, and hyphens a range. Sunday is 0.

ExpressionMeaning
*/5 * * * *Every 5 minutes.
0 * * * *At the start of every hour.
0 7 * * *Every day at 07:00.
0 9 * * 1-5Weekdays at 09:00.
0 9 * * 1Every Monday at 09:00.

Enabled and Registered

Enabled

Stored in the task definition. An Enabled task should be scheduled and is repaired by resynchronization.

Registered

Shows whether its mirror currently exists in Windows Task Scheduler. Register/Unregister changes that mirror.

The JSON task store is the source of truth. Task Scheduler mirrors only the next occurrence. After every run, the runner computes and registers the next one. Use Resync schedules to repair missing or stale registrations.

Run while logged off

Run when the user is logged off (S4U) allows execution without an interactive session. Scheduled tasks must use the same Windows account because DPAPI secrets, Google tokens, and %LOCALAPPDATA% are user-specific.

S4U cannot display Google consent. Connect Google in the UI before enabling this option.

Prompt-injection risk reduction

Understand the content trust filter

Gmail reads and http.get / http.getText responses are classified through a direct LLM call with no tools, skills, or agent loop. This probabilistic control does not replace Safety gates, tool whitelists, the filesystem sandbox, or the HTTP host allowlist.

Score/statusModel delivery
Clean, 80–100 by defaultMarked plaintext inside UNTRUSTED-EXTERNAL-DATA delimiters.
Caution, 50–79Marked UTF-8 Base64 inside UNTRUSTED-EXTERNAL-DATA-BASE64 delimiters.
Low, 0–49Content is withheld and replaced by a score marker.
ScreeningDisabled / FailedMarked Base64 for normal-size content.
Base64 is neither encryption nor a security boundary. A model can decode it and must still treat the decoded text only as data, never instructions.

Oversized content

Above MaxContentChars, deterministic ordered chunks cover every source character through sequential tool-less calls. The effective score is the minimum observed across the source and exact delivered summary block. A summary that exceeds its maximum is capped in C# with an explicit marker and forced to Base64. Content above MaxSummarizationSourceChars is never partially summarized.

  • Gmail preserves exact From, To, Subject, and Snippet values in one protected canonical block and replaces only Body with a summary or Gmail-review notice.
  • HTTP preserves URL, status, and content type, then returns a Skipped… notice without the page or a partial summary.
  • A positive Gmail limit processes only the first N messages with explicit counts and a warning; 0 is unlimited.

Trust filter page

Paste external text, optionally select Return Base64, then select Screen. The page separates trust status from processing status and shows score, provider, latency, lengths, protected preview, and validated verbatim indicators. Indicator text stays on this human page; Gmail/HTTP/Web Search tool output exposes only the count.

Settings, privacy, and limitations

Settings → General → Guardrails controls thresholds, size limits, reduction, timeout, the 24-hour in-memory cache, and Gmail limit. Turning off Use LLM guardrails processing does not turn off protection: normal content uses Base64 and oversized sources use the Gmail/HTTP notices.

With OpenAI-compatible selected, screened Gmail/HTTP/Web Search content leaves the machine. An oversized source may be sent completely through several sequential chunks. Do not use real private mail in a cloud test without explicit authorization.

False positives and false negatives remain possible, especially for encoded or obfuscated attacks. Dropbox, local files, Calendar, Gmail attachments, outbound content, and HTTP POST responses are out of scope.

Enter comma-separated host names in Allowed HTTP hosts, without protocol or path. An empty list allows all HTTP/HTTPS hosts. That can help during an interactive test but is not recommended for unattended tasks.

Select Debug (next run) before Run now to display that execution’s LLM requests and responses, along with the tool calls and arguments already present in the traces. A Gmail read also reports Guardrails progress as message N of M. With a zero Gmail limit and no maxMessages, every retrieved message is screened sequentially by the local model. Resolve common problems

Open a topic to see the recommended checks in order.

Ollama does not respond
  1. Run ollama list in PowerShell.
  2. Check that the standard local endpoint is http://localhost:11434.
  3. In Settings, select Refresh models.
  4. Save, then run Test connection.
  5. Check Logs if Ollama works from the command line but not from the application.
The configured model is missing

Install the missing tag, then refresh the list:

ollama pull gemma4:12b
ollama list

Select the exact same identifier in the Ollama combo box.

The runner cannot be found
  1. Check that the published layout contains Runner\OD.MyLocalAgent.Runner.exe.
  2. Leave Runner path empty for the standard UI/Runner layout.
  3. Otherwise, enter the absolute path to the published runner.
  4. Save Settings and run Resync schedules.
A task is no longer scheduled or shows Registered = No
  1. Check that the task is Enabled.
  2. Select it in Tasks and use Register to repair just that task.
  3. For global repair, use Dashboard → Resync schedules.
  4. Refresh Tasks and check the next run.
Google repeatedly requests consent
  1. Check that the OAuth client type is Desktop app.
  2. Confirm that the account is an allowed test user.
  3. Check that Gmail API and Calendar API are enabled.
  4. Complete consent from Tools in an interactive Windows session.
  5. Use the same Windows account for S4U tasks.
SafetyException blocks an operation

Read the exact required setting. Review the workflow, whitelist, destination, and input data. Then enable only that setting under Settings → Safety gates.

A filesystem path is rejected

Use a relative path such as reports\summary.md for RootPath, or add the absolute directory to the task's Authorized locations. Check the required read/write mode, Windows permissions, and unavailable volumes. ..\ traversal remains rejected.

An HTTP request is rejected
  1. Check the host name in Allowed HTTP hosts, without protocol or path.
  2. For POST, enable Allow HTTP POST only after reviewing the body.
  3. For GET, verify the URL and endpoint certificate.
  4. Use Tool tester to isolate the call.
